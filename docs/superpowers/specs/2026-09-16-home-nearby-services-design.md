# 和伴首页附近服务优化规格

## 目标

结合参考页面的“附近服务”和“距离筛选”体验，增强首页的即时服务感，同时保持和伴现有亮色、移动端优先的视觉基调。

## 首页结构

首页内容顺序调整为：

1. 顶部品牌与消息入口
2. 主视觉轮播
3. 黑色欢迎条与今日档期
4. 附近服务
5. 三个核心服务入口
6. 档案与档期、进程订单、优惠卡兑换、意见反馈群
7. 热门服务
8. 底部导航

## 附近服务模块

模块标题使用“附近服务”，副标题显示当前城市和附近可服务的小伴数量。

模块提供：

- 当前城市切换
- 定位入口
- 距离筛选：1 公里、3 公里、5 公里、全城
- 当前筛选结果统计
- 附近服务人员头像叠放展示

第一版使用本地演示数据，数据结构预留：

```ts
interface NearbyProvider {
  id: string;
  name: string;
  avatar: string;
  city: string;
  distanceKm: number;
  categories: string[];
  online: boolean;
}
```

## 主服务入口

保留现有三张核心入口卡：

- 健康医陪
- 宠物陪伴
- 自定义服务+

卡片继续承担业务跳转，不把距离筛选和订单填写混入卡片内部。

## 热门服务

参考第二张图，将热门服务改为可横向滚动的轻量分类入口，每项使用独立图标和浅色背景：

- 陪诊协助
- 家政生活
- 同城跑腿
- 线下摄影
- 线下陪玩
- AI 沙龙

热门服务只负责进入对应服务目录或需求发布流程，暂不直接创建订单。

## 发布入口

首页和社区统一使用页面框内右下角圆形 `+` 按钮，避免长文本按钮溢出移动端容器。

点击后进入发布审核流程，字段与现有自定义任务页保持一致：

- 事件主题
- 日期和具体时间
- 服务地点
- 服务对象
- 人员要求
- 需求详情

## 数据与后端预留

前端先使用本地演示数据，但组件接口按照后端可替换方式设计：

- `NearbyProvider[]`：附近服务人员
- `distanceKm`：距离排序与筛选
- `categories`：服务大类映射
- `online`：在线状态
- 发布任务保留 `status: pending_review`

后续接入真实定位、服务人员查询和审核接口时，不改变首页组件结构。

## 交互规则

- 距离筛选只影响附近服务模块。
- 切换城市后重置距离筛选为“全城”。
- 无附近服务时显示空状态，并保留“发布自定义需求”入口。
- 所有按钮保持移动端稳定尺寸，文字不依赖横向溢出。
- 不增加暗色主题或大面积渐变，保持现有品牌色。

## 验收标准

- 首页首屏可看见附近服务模块的标题和距离筛选。
- 430px 宽移动端无横向溢出。
- 距离按钮可切换并更新统计数字。
- 三个核心服务入口原有跳转不受影响。
- 右下角 `+` 按钮位于应用容器内。
- 首页构建、刷新和 GitHub Pages 部署均不出现白屏。
